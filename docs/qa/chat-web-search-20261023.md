# Chat 联网检索

## 行为与边界

Chat 的文字与语音转写走同一接口。明确说“联网搜索”“查一下”“核实”或询问最新、当前、今年等资料时，代码直接发起一次 MiniMax MCP `web_search`，无需增加模型分类请求。普通知识问答不搜索，“不要联网”“不需要联网”等约束优先。询问“你能联网搜索吗”只说明能力，不触发搜索。

示例：

- 联网查询中国2024年末全国人口总数，引用国家统计局来源，注明统计时点和口径。
- 联网核实刚才的说法。
- 不要联网，解释人口普查和人口抽样调查的区别。

搜索只开放给 Chat，不允许 Operate 调用，不会执行网页中的操作指令。现阶段用于文字问答；图片理解、图片生成、教案设计仍沿用各自服务，不组合执行网页检索。

每回合最多一次搜索、最多五个有效来源，不自动重试。搜索按供应商规则计费，是独立工具调用，通过 `search_calls`、`search_ms` 计时；不属于推理生成请求，回答仍受现有三次模型请求上限约束。普通成功搜索问答为一次搜索加一次模型请求。

## 数据与真实性

MCP 返回标题、链接、摘要、可选资料日期。只使用实际返回的有效 HTTP(S) 来源，过滤空摘要、重复链接、非法协议和明显本地地址；后端不访问结果链接、不自动下载网页。摘要有大小限制，以不可信资料注入，不授予任何工具权限。日期缺失明确显示“未提供”。

模型使用对应来源编号回答。检索时点和本次实际使用的有界摘要保存在 Job 的 `retrieval_trace`，来源保存在结果和会话中。模型应区分检索日期、发布日期、数据年份及统计口径；检索摘要不等于阅读全文，也不自动证明内容准确。摘要不足或冲突应说明限制。

失败、未配置或无有效摘要返回 `partial`，不再调用模型凑出联网答案；取消继续沿用任务取消与 MCP 子进程终止机制。原始供应商报错、进程 stderr 和凭据不进入用户消息。

## 界面

复用现有一行活动与折叠详情：正在调用工具 · 联网搜索 → 正在核对搜索资料 → 整理回答 → 流式回答。完成后显示用时与回答；“参考来源”展开查看链接与资料日期，不新增调用次数或 token 展示。

## 配置

`WEBGIS_AI_WEB_SEARCH_ENABLED` 默认 `true`，可设 `false` 关闭。复用已有 `WEBGIS_AI_MINIMAX_TOKEN_PLAN_KEY` 或 MiniMax API Key、MCP 命令与地区 host；不依赖图片理解开关。Key 必须具备供应商搜索权限。

官方工具协议：https://github.com/MiniMax-AI/MiniMax-Coding-Plan-MCP
