## Result and preserved behavior

Top-level and embedded teaching contexts are checked before image resolution, Job creation and worker start. Internal engine handling checks before memory seeding or compression. Session statistics require an explicit project ID. Event logging uses the actual Job's project. Direct tool execution, its live-class validator and runtime tool dispatch also enforce the binding. Approval and rejection recheck both historical payload and frozen-plan contexts before changing the confirmation or memory.

An explicit unknown session is rejected; a session belonging to another project, a conflicting optional context project ID or a conflicting lesson ID is rejected. Contexts without a session remain valid. Ended sessions remain readable for reflection. No global lesson lookup is required for historical session references, preserving immutable lesson snapshots and older sessions whose original lesson is no longer present.

Lesson records have no project ID: built-in sharing and teacher reuse across projects are not replaced with a fictitious project-lesson relation. This task establishes session/project and session/lesson consistency. Authorization of a private lesson ID without a session, including IDs generated by the planner, remains the next separate S2 task; this record does not claim that gap is fixed.

HTTP endpoints, normal response shapes, tool names, task statuses and persistence formats are unchanged. The internal statistics-provider callable now receives `(project_id, session_id)`; all repository call sites were updated. Active mutation tools retain their existing running-session checks. No current-stage fallback was added to question launch.
